## 3. 失分结构：查询侧与负例侧是两类问题

C 批 dev 959 分层（`artifacts/eval/v3/es-hybrid-rerank/RESULT.md` §3）：multi_intent 83.3%（n=51）、pinyin 85.0%（n=20）、noisy 88.2%（n=51）为最低三档；typo/ellipsis 100%；全对 786/838=93.8%。归档轮严格口径同样指向 pinyin/noisy/typo 为最弱分层（`RESULT-gate.md`）。

- **查询侧（multi_intent / pinyin / noisy）**：检索器已能处理错字（typo 100%），但**多意图、拼音混输、口语噪声**的查询理解仍不足——属查询改写/拆解与词表覆盖面问题，补强方向是查询侧（多查询拆解、词表扩充、规范化臂），不是继续加文档。
- **负例侧（拒绝率 58~60%）**：归档已定位高分负例集中在 **F 类外部机构文档**（品牌延保、外部赔偿条款等 0.99+ 命中），检索器没有「平台规则 vs 外部机构条款」的区分能力；属**语料入选规则与权威性排序**问题，补强方向是负例侧（外规 relabel/入选 + 平台优先 + 近域负例生成），不是查询改写。

两侧必须分开成臂，避免用查询侧增益掩盖负例侧缺口（或反向）。

## 5. 门禁与校准设计（若将来实施）

- **数据集**：dev 959（`app/evaluation/retrieval_cases_v3.json`，sha256 `01e98071182a7cbe7e8395a2286bcfa62a5214007bf327290df582a2a41015f5`）用于校准与迭代；**holdout 250 已于 2026-09-18 C5 一次性消费**（C4 校准用的 175 例 holdout 同样已消费，`params.json` 记 `holdout_used=true`），v3.5 判读必须新建独立冻结 holdout（或显式声明失去独立性），不得复用已消费集合。
- **判读阈值（双轨，沿用 P1-5 §5.3）**：
  - 相对判读（唯一可执行）：负例拒绝不得低于 Arm 0（n=121，95% CI ≈ ±8.3pp，只看方向不看小数）；hard 不得低于 Arm 0 − 2pp（n=334，±4.6pp）；正例/easy 不得低于 Arm 0 − 1pp。任一项越界 → 不合并。
  - 绝对判读：只有 Arm 0 在新索引上重跑留档后，才允许谈「是否达到 90%/80%」；若负例拒绝跨过 ≥90% 且正例误拒 ≤5%，属**新冻结口径**，对外数字须整体替换，禁止新旧混用。
  - holdout 判读只作「方向不相反」的独立佐证（负例 n=50，95% CI ≈ ±13.9pp），不作为通过依据。
- **校准**：任何改变 Top-K 构成或分数尺度的臂，都必须重跑 `calibrate_rejection --dev` 重新冻结参数并写回 settings（阈值与分数尺度绑定）；`online_threshold_match=true` 后才可出结论。
- **回退**：语料/入选规则类改动 → 恢复 `is_index_eligible`/`validate_metadata`/relabel 原状并重建，`--no-activate` 构建后由 `GenerationStore.activate` 原子切回，旧代际指针保留可回滚；查询侧改动 → 词表/overlay 回退不重建索引；阈值 → 回退到 C4 冻结值 0.206。
- **指纹 bump**：语料入选规则/切分输出变化 → bump `PARSER_CHUNKER_VERSION`，入选规则建议进 `config_fingerprint`（否则关掉规则后旧索引被静默复用）；打分侧（权威性排序/降权）→ 必须进 `config_fingerprint` 且重建 + 重校准；词表/overlay 变更 → 词表哈希随 manifest 留痕，不重建索引。细则对齐 P1-5 §5.5 表。
