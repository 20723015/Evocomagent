# 安全修复计划 · 执行基线（含评审修订）

> 本文档是《安全修复计划》经评审后的执行基线：缺陷清单经逐条代码核对属实，
> 评审发现的 5 个实现层坑已并入对应条目（标记 **[修订]**）。变更基于
> `2587d47`，发布为 **0.3.0**；GET SSE 弃用一个版本后 0.4.0 删除。

## 分期与执行顺序

- **P1 资金/越权**：RBAC、审核后台、退款幂等状态机、MCP 身份（四块独立硬骨头）
- **P2 语义/韧性**：SSE 租约重构、LLM timeout 接线、路径穿越、500 脱敏、
  存储后端开关、LTM 原子 merge + 巩固水位
- **P3 配置/发布**：mcp 钉版、GET SSE 弃用标记、版本号、文档

假设（诚实声明）：旧 session_id 不迁移；进程内退款/幂等存储不提供跨进程保证
（生产必须配 Redis）；mock 退款执行器无下游去重语义。

## P1

### 1.1 运营端点 RBAC
- 缺陷：`/v1/handoffs`（创建/列表/回写）与 `/v1/messages/search` 无 scope 校验，
  `AUTH_ENABLED=false` 时全网裸奔。
- 修复：新增 `app/security/principal.py`（Principal + scope 校验依赖）。
  JWT 增加 `scope` 声明；运营端点要求 `ops` scope（messages/search 另允许坐席
  读 scope `ops`）。`auth_enabled=false` 且未强制时保持开发直通（测试/本地），
  新增 `OPS_RBAC_REQUIRED=true` 可在不开启用户鉴权时单独强制运营面鉴权。
- **[修订]** 开发工具：新增 `app/scripts/issue_token.py`（`--user --scopes --ttl`），
  否则 RBAC 落地后本地 curl 全部失效，第一个跑测试的人就会卡住。

### 1.2 审核后台认证 + CSRF + XSS
- 缺陷：`app/review/webapp.py` HTML 模板直接注入 `{question}`；无登录无 CSRF；
  任何人 POST /approve 即可写知识库（→ 检索 → prompt 注入入口）。
- 修复：`REVIEW_ADMIN_TOKEN` 未配置 → 整站 503 fail-closed；登录签发
  HttpOnly 签名会话 cookie；表单带 CSRF token（HMAC 会话密钥）POST 校验；
  全部插值 `html.escape`。

### 1.3 退款幂等状态机
- 缺陷：`RefundConfirmation._executed` 是实例字段，而 `apply_refund` 每次调用
  新建控制器——进程内字典永远为空，幂等从未生效；幂等键由「订单+原因」派生，
  把同单同因的正当二次退款误判成重放。
- 修复：幂等账本进共享 store（`refund_id → 结果`，Redis NX+TTL / 进程内）；
  幂等锚点改为 `request()` 签发的 **refund_id**（不再用订单+原因哈希）；
  confirm 状态机：已执行 → 返回首次结果 `replayed=true`；token take 单次有效
  天然拒绝并发双确认；同单同因可再次发起（订单层防双退仍由
  refund_processing 状态兜底）。
- **[修订]** 验收措辞：mock 执行器没有下游去重语义，「执行后崩溃重试只执行
  一次」只有真实后端能保证。测试只断言三件事：① executor 收到的幂等键一致；
  ② 状态机拒绝并发双确认（token 单次）；③ 重复 confirm 跨控制器实例返回
  `replayed=true` 且 executor 恰好一次。不写「下游只执行一次」的假验收。

### 1.4 MCP 身份与归属
- 缺陷：MCP server 零认证；经 MCP 调用时 `ctx=None`，归属校验
  `if user_id and ...` 直接跳过——ownership 强制可被 MCP 路径绕过。
- 修复：server 侧 Bearer 校验（`MCP_AUTH_TOKEN`，配置后拒绝匿名；uvicorn 挂
  Starlette 中间件实现）；工具包装层以 `MCP_ACTOR_USER_ID` 构造 ToolContext；
  `_check_ownership` 改 **fail-closed**：enforce 开启且拿不到身份 → 拒绝
  （不再放行），同步修改旧行为注释。

## P2

### 2.1 SSE 会话租约 + 断连保护
- 缺陷：`main.py` 的 `with SessionLease(...)` 在路由 `return StreamingResponse`
  时退出——生成器实际消费在锁释放之后，流式期间会话无保护。
- 修复：租约获取/释放移入生成器体内（acquire 失败→ 流内 error 事件，语义与
  现有限流/冲突路径一致），生成器 finally 释放。
- **[修订·坑1]** 断连后「等待不可中断的 Agent 工作结束」必须有上限，否则
  恶意客户端批量连接后立刻断连可占满 32 线程池（slowloris 变体）。等待上限
  = `max_react_steps × llm_timeout_seconds`（含重试余量 ×1.5）；超时记日志、
  收尾交线程自行完成，不再调用 close。
- **[修订·坑3]** GeneratorExit 清理雷区：清理路径不得在生成器 finally 内
  直接 await 可能 yield 的操作。实现模式：收尾（agent close + 用量记账）放
  请求 cancel scope 之外的独立 `asyncio.create_task`，`asyncio.shield` 保护，
  生成器 finally 只负责触发与租约释放。验收补一条「断连后无线程/锁泄漏」。

### 2.2 LLM timeout 接线
- 缺陷：`deadline_ms` 算完从未使用；`deps.py` 构造 `OpenAI()` 未传 timeout——
  SDK 默认 600s 生效，`llm_timeout_seconds=60` 是死配置。
- 修复：OpenAI client 构造传 `timeout=settings.llm_timeout_seconds,
  max_retries=0`（重试由韧性包装负责，避免 SDK 重试叠加）；删除死变量；
  `EcomAgent` 自建兜底 client 同步接线。

### 2.3 user_id/session_id 路径穿越
- 缺陷：标识无字符集校验，直接拼 `{session_dir}/{user_id}/{session_id}.json`
  与 LTM 文件名，`../` 可逃逸。
- 修复：`validate_identifier`（`^[A-Za-z0-9][A-Za-z0-9._-]*$`，长度上限）；
  入口（pydantic 模型 + authenticate_user）与存储层（file/Redis key 构造）
  双层校验，存储层拒绝即抛 `SessionOwnershipError` 语义的 4xx。

### 2.4 500 泄露异常细节
- `detail=f"内部错误: {exc}"` → 固定文案，细节仅留日志（trace_id 关联）。

### 2.5 SESSION_STORE_BACKEND 死配置
- 缺陷：deps 只看 Redis 连通性，从不读该开关。
- 修复：`db_url` 配置 → SQL 正本（不变）；否则按 `session_store_backend`
  选择 redis/file：显式 `redis` 而不可用 → 按 `redis_required` 决定
  fast-fail 或降级 file（warn）；显式 `file` 时 Redis 仅保留锁/限流角色。

### 2.6 LTM 并发覆盖 + 重启重复巩固
- 缺陷：`_consolidated_len` 水位只在内存，重启归零 → 全量重巩固（重复摘要）；
  同用户多会话并发 load/extend/save 互相覆盖（last-write-wins）。
- 修复：
  - 水位持久化：`SessionState.consolidated_len` 入 store（v2 payload 增字段，
    旧数据无字段 → 视为已巩固，避免升级后立即重复摘要）。
  - 原子 merge：LTMStore 增加 `merge(user_id, merger)`——文件版 per-user 锁、
    Redis 版 WATCH/MULTI 重试、SQL 版事务内读-改-写；`LongTermMemory` 写路径
    改走 merge。
- **[修订·坑4]** fakeredis 对 WATCH/MULTI 支持有限，竞态测试只跑 SQL（sqlite
  事务）/文件锁路径；Redis merge 只用 fakeredis 验证合并正确性（不验证竞态）。

## 与原计划的差异（决策记录，评审二轮补记）

> 首轮实施后经二轮评审逐条核对：A/B1/B2/B3/B5/D 已在二轮补做并带测试；
> C1/C2/C3 为有意取舍，在此显式记账；P3 剩余项列为下一批。

### 二轮已补做（2026-08-29）

- **A 升级迁移**：`deploy/sql/002_migration.sql` + 启动探测补列
  （`engine._ensure_upgrades`）。`create_all` / `IF NOT EXISTS` 都不会修改
  已存在的表——阶段八老库升级后缺 `sessions.consolidated_len` 列会直接
  OperationalError，现启动时自动 ALTER（sqlite/MySQL 通测），失败
  fail-fast 提示手工迁移。
- **B1 reset 抢锁**：`/v1/sessions/reset` 持会话锁（写操作），被流式/对话
  占用时 409。
- **B2 用量 request 粒度**：UsageTracker 弃 per-user 桶改 per-request 桶；
  ContextVar 随 anyio to_thread 拷贝传播——turn 线程与 **close 阶段**
  （LTM 巩固 LLM 调用）都归到本请求；同用户并发会话不再混账；断连弃单的
  陈旧桶有清扫兜底；end_request 幂等配对。
- **B3 LLM 总截止**：韧性包装加单调时钟总预算 =（重试+1+降级一次）×单次
  超时；「剩余预算放不下一次完整调用」即止损（检查在每次尝试之前），退避
  睡眠夹到剩余预算内，降级链同样受约束。最坏墙钟从开放级数变为 ≈预算+一次
  超时。
- **B5 trace_id**：500 与流内 error 事件携带 `trace_id`（OTel span 有效时
  取其 trace_id，否则 16 位随机 id），服务端日志同 id 对账。
- **D 小项**：MCP Bearer 改常量时间比较；审核后台会话 cookie
  SameSite=Strict + `REVIEW_ADMIN_COOKIE_SECURE`（TLS 部署开启 Secure 位）。

### 决策（有意取舍，代价已明确）

- **C1 MCP 静态 actor（替代 per-user 短期 actor token）**：
  `MCP_ACTOR_USER_ID` 是全局身份。安全上成立（归属校验 fail-closed，
  MCP 路径无法绕过），但 `enforce_order_ownership=true` 时 MCP 的订单/
  退款工具对真实用户订单**全部拒绝**（mcp-actor 名下无订单）。若生产仍需
  经 MCP 操作用户订单，需实现 per-user actor token——已记账为债务。
- **C2 单一 `ops` scope（替代 handoff:read/write、knowledge:review 细分）**：
  坐席与审核员暂不分离；scope 精化随下一批 RBAC 迭代。
- **C3 运营端点开发直通（默认与计划原文相反）**：`auth_enabled=false` 且
  `ops_rbac_required=false` 时匿名放行——保住本地/测试工作流；生产靠
  `AUTH_ENABLED=true` 或 `OPS_RBAC_REQUIRED=true` 收紧（两开关均有测试）。
  计划原文是「即使 AUTH_ENABLED=false 也必须携带运营 JWT」，实现给了
  显式开关而非改变默认。
