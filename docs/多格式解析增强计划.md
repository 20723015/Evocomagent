## 批次 1：PDF 表格抽取（引入 pdfplumber）

**问题**：`_parse_pdf` 只用 pypdf `extract_text()`，表格退化成乱序词串，行列对应关系丢失；且 PDF **没有**任何标题识别，`heading_path` 永远只有「文档名 > 第 N 页」。

**改动**：

1. `requirements.txt` 增加 `pdfplumber>=0.11`；`requirements-dev.txt` 增加 `reportlab>=4`（顺带修复 `app/scripts/convert_kb_docx_pdf.py:73` 未声明的隐式依赖）。
2. 重写 `parsers._parse_pdf`（`parsers.py:59-78`）：
   1. pdfplumber 打开，逐页**廉价预检** `page.lines` / `page.rects`：无线条/矩形的页（纯文本页、扫描页）直接 `extract_text`、跳过 `find_tables`。这是 30s 超时对策——`settings.kb_upload_parse_timeout=30`，`parse_guard.parse_with_timeout` 杀子进程是**上传失败、不是进程内回退**，`find_tables` 在 200 页上限内可能超时。
   2. 有线/矩形页 `find_tables()` 取 bbox；表外文本用 `page.crop(bbox).extract_text()`，按阅读序交错输出「表前文本 / 表 / **表间文本** / 表后文本」（多表页泛化，非只表前/表后）。
   3. 每表转 Markdown：首行作表头 + `| --- |` 分隔行，空单元格留空，**单元格文本 `|` 转义为 `\|`**（防止列错位）。
   4. 保留 `# {文件名}` 一级标题与 `## 第 N 页` 章节结构不变。
   5. **回退粒度 = 整篇**：任一页异常或全篇零表格命中 → 整篇回退现有 pypdf `extract_text()` 路径，绝不混合双引擎输出（同文档词序一致性）。
3. 页数上限仍由 `upload_service._page_limits`（pypdf，`upload_service.py:1687-1702`）把关，解析前生效，不动。

**测试**：新增 `tests/unit/test_parsers_tables.py`
- reportlab 造带边框表格 PDF（`pytest.importorskip`）→ 断言 pipe 表 + `| --- |` + 行列不串位 + 表外文本保位；
- 无表格 PDF → 输出与现有路径**逐字节相等**（复用现有 `_build_pdf` 手写夹具，断言完整输出字符串）；
- 全空页 → 仍报「扫描件走 OCR」；
- 预检逻辑单测：无 rect/line 的页不触发 `find_tables`（monkeypatch 计数）；30s 子进程超时本身不进单测。

## 批次 4：md/txt/html 编码回退

**问题**：`read_text(encoding="utf-8")` 写死，GBK 文本抛 `UnicodeDecodeError`（`ValueError` 子类）→ strict 构建中止、非 strict 静默跳过。HTML 更糟：`errors="replace"` 让 GBK 页面**静默乱码入库**。

**改动**：

1. `loader.py` 新增 `decode_text(raw_bytes) -> str`：
   - 依次尝试 `utf-8` → `gb18030`；
   - **删除 utf-8-sig**：BOM 是合法 utf-8 且 `normalize_document` 已剥，永不可达；
   - **解码后守卫**：含 `\x00` 或不可打印控制字符（`\x00-\x08\x0b\x0c\x0e-\x1f`）占比 > 2% → 视为失败（gb18030 能「成功」解码大多数随机字节，无守卫则「二进制仍失败」语义不成立）；
   - 全失败抛 `ValueError`；不引入 chardet。
2. 替换 **5 处**写死的 utf-8：

   | # | 位置 | 说明 |
   |---|---|---|
   | 1 | `parsers.py:41` | md/txt 直读 |
   | 2 | `parsers.py:277` | `chunk_kb_dir` 里 md/txt 的 raw 直读 |
   | 3 | `parsers.py:200` | html（原 `errors="replace"`，属修复而非防崩溃） |
   | 4 | `chunker.py:97` | `_chunk_one_file`，生产调用方 `evolution/index_service.py:170`（`chunk_markdown_dir`） |
   | 5 | `check_kb_governance.py:38` | CI 门禁，不改则 GBK md 入库后门禁脚本崩溃 |

**测试**：GBK 编码的 `.md`（含 frontmatter）/`.txt`/`.html` 正确解析；`os.urandom` 二进制伪装 `.txt`（含 NUL）仍抛错；GBK md 过 governance 检查不崩。

## 批次 5：长表格按行切分（表格行感知）

**问题**：`_SENTENCE_END = "。！？；.!?;"`（`chunker.py:59`）不含 `\n`，但含 `.` 与 `；`。表格行以 `|` 结尾、无句末标点，因此：

- 含 `0.5%` 的费率行会被 `.` 命中、**在数字中间切开**；
- 纯文字表格行无断点 → 落到 `_hard_spans` 按字符数硬切。

**改动**（三层）：

1. **表格行原子化**：`_sentence_spans`（`chunker.py:336-352`）预扫描行偏移，strip 后以 `|` 开头的行 = 表格行；行内（不含结尾换行）**禁用一切标点断点**；行尾 `\n` 之后作为断点 → 每行一个 span，交给既有 `TARGET_CHUNK_CHARS` 打包逻辑；
2. **全局小数点保护**：`.` 两侧均为数字时不作断点（`3.9`、`0.5%` 不再从中间切开）；「数字 + `.` + 空格」（编号列表 `1. `）不保护、行为不变；
3. 单行仍超 `body_limit` → 维持 `_hard_spans` 字符硬切（最后兜底，已知边界）。

不动全局 `_SENTENCE_END`；fence / 行内图片链接的原子保护不变；**非表格文本切分行为不变（唯一例外：小数点保护）**。

既有硬断言已核不受影响：`test_chunker_headings.py:147`（用例无换行无小数）、`:210`（走段落打包而非兜底切分）；现网语料 0 个受影响分区。

**测试**：超长无标点表格块 → 子块以行边界结尾、无 mid-row 硬切；含 `0.5%` / `1.5%` 行不在数字中间切开；非表格超长文本切分与现状逐字节一致（回归）；单行超限仍硬切（边界用例）。
